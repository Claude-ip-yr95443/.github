<p>号一多，「池子」这个词就会冒出来。但池子本身不解决问题，怎么从池里取才解决问题。下面按实际会遇到的五个问题一个个串下去：池多大、怎么防撞、占用谁记、多久轮一次、撞了怎么办。每个问题都给出可执行的判断标准。</p>
<h2>一、先算池子多大，再谈怎么取</h2>
<p>先算一个下限：同时在线的号数乘以一点五，是这个池子比较舒服的规模。乘以一点五的意义在于留出轮换与坏线剔除的余量，池子刚好等于号数时，一条线出问题就没有替换空间。</p>

<h3>为什么不是越大越好</h3>
<p>池子越大，验收工作量越大，未验收的线混在里面反而增加风险。六十条里如果有十条从没跑过长会话，这十条就是随时会爆的雷。</p>
<h3>什么时候该扩池</h3>
<p>连续两周出现「所有线都在占用，新号排不上」的情况，就该扩。扩之前先确认现有池里没有长期闲置的线，闲置往往意味着没验收或已经坏了。</p>
<h3>撞车概率的粗算</h3>
<p>靠随机取，撞车概率比想象中高得多。池里五十条线、二十个号随机分配，至少有一对撞车的概率接近九成八。所以「轮流从池里取」必须有占位记录，不能靠运气。</p>
<p>用生日问题的近似公式：撞车概率约等于 1 减去 e 的负（k×(k-1)÷(2N)）次方，k 是号数，N 是池大小。五十条池子、二十个号代入，指数约 3.8，撞车概率约 98%。这个数字说明随机分配基本不可用。</p>
<h3>确定性的分配办法</h3>
<p>维护一张占位表，记录每条线当前绑定的账号编号。取线时按编号顺序找第一条状态为「空闲」的，取到立刻改写状态。规则简单到不需要思考，也就不会出错。</p>
<h2>二、占用关系谁来记</h2>
<p>多人协作时，记在哪里比记什么更重要。放在共享表格里，谁都能看能改；放在某个人电脑里，等于没记。表格至少要有五列。</p>

<h3>加一列「最近一次会话」</h3>
<p>记录这条线最近一次跑通长会话的日期。超过两周没跑过的线，再次启用前要重新验一次，避免拿到一条已经坏掉但状态还写着「空闲」的线。</p>
<h3>并发修改怎么办</h3>
<p>两个人同时改同一行，后改的会覆盖前一个。最简单的办法是约定「改前先看时间戳」，或者用表格的编辑历史回溯。规模再大就上带锁的脚本。</p>

<h2>三、轮换的节奏怎么定</h2>
<p>轮换的目的是把长期运行的线换下来歇一歇，同时让每条线都保持可用状态。节奏太快，环境频繁变；太慢，坏线发现得晚。</p>
<h3>按批次轮换，不按单条</h3>
<p>一次换三到五条，换完观察一天。单条零散地换，等于每天都在变化，日志没有稳定基线。批次轮换能让「换线之后有没有变差」这件事看得出来。</p>
<h3>什么线该优先换下来</h3>
<p>优先换运行时间最长的、以及最近一次会话表现最差的那几条。换下来的线不立刻停用，先放进「观察」状态，跑一次长会话确认状态。</p>
<h2>四、撞车之后怎么处置</h2>
<p>撞车指的是同一个出口被两个号先后使用，或者两个号同时在用。发现之后不要慌，先确认时间是否重叠，再看两个号的异常是否同时出现。</p>
<h3>处置的三步</h3>
<p>第一步把后来者的绑定关系改到空闲线；第二步查两条日志的时间重叠区间，确认影响范围；第三步把这次事件记进台账，写明原因——是占位表没更新，还是有人绕过了流程。</p>
<h3>怎么减少再次发生</h3>
<p>把取线动作收敛到一个入口：要么统一由一个人分配，要么统一走脚本。入口一多，占位表必然失真。这条比任何提醒都管用。</p>
<h2>五、把五个问题串成日常流程</h2>
<p>每天的动作其实很简单：早上看一遍占位表，确认空闲线数量够当天的号用；分配时改状态；晚上把当天异常写一行；每周挑一个批次轮换；每月核对一次绑定的悬空记录。</p>
<h3>每周要做的一次核对</h3>
<p>把占位表和平台侧的实际使用情况对一遍，找出「表里写着占用但实际没人用」和「表里写着空闲但账号还在用」两类悬空记录。这两类是撞车的主要来源。</p>
<h3>什么时候该重做整套流程</h3>
<p>账号规模翻倍、增加新城市、团队新增成员，这三种情况都要重新过一遍流程。流程不会自己长大，规模变了还按老办法，撞车就会回来。</p>
<h2>常见问答</h2>
<h3>池里的线要不要全部保持在线？</h3>
<p>答：不必。空闲线可以只保留配置，不跑流量。但每隔两周要跑一次长会话确认可用，否则「空闲」只是纸面状态。</p>
<h3>用脚本分配会不会更容易出错？</h3>
<p>答：脚本出错通常是一次性的、可复现的，改一次就好；人工分配出错是随机的、难追溯的。有规模之后脚本更可靠，前提是加上失败重试与结果回读。</p>
<h3>同一城市的多条线可以混用吗？</h3>
<p>答：可以，但绑定关系要固定。同一个号不要在城市内的多条线之间来回换，换城市可以解释，同城来回跳没有合理解释。</p>
<h3>撞车一定会导致账号异常吗？</h3>
<p>答：不一定，但风险会上升。处置的重点是尽快恢复一对一绑定，并记录清楚，避免同一对号反复撞。</p>
